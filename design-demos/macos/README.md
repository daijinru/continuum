# Continuum · macOS 交互方向评审

对应 [Issue #3](https://github.com/daijinru/continuum/issues/3)。**待选择**，这里是可离线试用的界面初稿，不是已上线的工作台。打开 `dir-a.html` 后，可在页顶切换三个完整 HTML。每个方向都使用同一组明确标注的示例，不读数据库、不建任务、不发网络请求；只有手动打开来源链接时才离开预览。

| 方向 | 首屏/主动作 | 取舍 |
|---|---|---|
| [A 对话工作台](dir-a.html) · [桌面](a-desktop.png) · [窄屏](a-mobile.png) | 窄来源栏、单流消息、固定输入。直接在结果下回复，不必先选任务。 | 最适合一个主对话；大量长报告需要提取摘要。 |
| [B 交付阅读器](dir-b.html) · [桌面](b-desktop.png) · [窄屏](b-mobile.png) | 把交付索引与正文分开，选择「周会提醒」只切换阅读对象。底部输入仍发往同一个对话，点「回复这条」才带入对象。 | 便于批量读报告，代价是默认视线从对话移向结果。 |
| [C 快速面板](dir-c.html) · [桌面](c-desktop.png) · [窄屏](c-mobile.png) | 输入在最前，委托和结果以短行呈现，只在需要时展开。⌘K 聚焦，⌘↵ 发送，Esc 关闭弹层。 | 短指令路径短，长篇阅读多一次打开。 |

试用顺序：问一次进度，打开一条结果，针对该结果说「以后多关注离线工具」，最后不带引用交代一件新事。比较哪一版最容易看清回复对象，哪一版需要最少切换。

## 设计依据

采用 [Huashu Design 3.5.0](https://github.com/alchaincyf/huashu-design/tree/59065698ad63f87ea1532c126c87f488d4f93fd6) 的网页模块、方向探索和截图打磨方法。共同约束：桌面 1440 × 900、窄屏 375 × 812；系统字体、正文至少 14px、深浅配色、显式焦点。三版从同一个主对话和多委托模型出发，不以并列聊天窗口或技术仪表盘替代产品。

候选：对话时间流、分栏阅读、命令面板、Finder 式多列目录、日历优先、菜单栏弹窗。前三者分别改变输入、阅读与状态查询的顺序；后三者分别会增加层级、过度突出排期、限制长文可读性，因此留作备选。参考上游 `native-polish` 的行/详情层次、`editorial-reader` 的阅读顺序和 `command-palette` 的键盘交互；没有复制样张皮肤。

品牌与内容：沿用项目的 Continuum 名称与连续环符号，不仿造没有实际作用的 macOS 窗口按钮。推荐案例使用 [LosslessCut README](https://github.com/mifi/lossless-cut#readme) 可核实的免重编码粗剪能力；图标源自[该项目](https://github.com/mifi/lossless-cut/blob/master/src/renderer/src/icon.svg)，这里只用于标识来源。不声称该项目进入任何当天榜单。
